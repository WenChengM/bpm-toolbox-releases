## 一、工具簡介與發行版本說明

BPM Toolbox 是專為企業級 BPM 系統（JBoss / WildFly 架構）打造的一站式輔助工具，提供修正檔案精準佈署、版本路徑反查、分支異動比對與全域字典掃描功能。

針對不同的應用環境與資安權限，官方公開發行兩款專用版本（核心研發管理版僅限內部構建使用）：

| 版本名稱 | 適用對象 | 提供功能 | 安全特性 |
| :--- | :--- | :--- | :--- |
| **現場客戶端部署專用版**<br>`bpm-deployer-client.zip` | 客戶端現場維運人員、客戶現場工程師 | 僅啟用「修正佈署」單一精簡介面 | • 排除內部異動記錄資料<br>• 隱藏路徑掃描與設定面板<br>• 現場操作最簡化、零機密外洩風險 |
| **內部維運作業專用版**<br>`bpm-toolbox-internal.zip` | 內部技術顧問、客服、維運團隊 | 啟用「修正佈署」、「路徑查詢」、「異動記錄」 | • 內嵌完整歷代版本異動資料庫<br>• 支援跨版本差異檢索與路徑比對<br>• 隱藏代碼級掃描與環境設定 |
| *(內部專用)* **開發管理者整合版**<br>`bpm-toolbox-dev.zip` | 核心研發工程師、系統管理者 | 全功能開放（含「路徑掃描」與「全域設定」） | • 支援實體 BPM 目錄掃描與建立 Master Index 字典<br>• 限內部原始碼庫構建，不對外公開發布 |

> **安全防禦設計**：直接雙擊 `bpm-toolbox.jar` 啟動時，系統一律預設為「現場客戶端部署版」，確保工具外流時不會暴露任何內部資訊。

## 二、快速上手指南

### 1. 系統需求
* **作業系統**：Windows 7 / 10 / 11 / Windows Server 2012+
* **Java 執行環境**：Java 8（JRE 1.8）或更新版本（支援 OpenJDK、Oracle JDK）
* **硬體螢幕**：內建 HiDPI 高解析度自動縮放，支援 2K / 4K 螢幕平滑字型渲染。

### 2. 下載與解壓縮
1. 前往發布頁面下載對應的 ZIP 壓縮包（例如：`bpm-deployer-client.zip`）。
2. 將壓縮包解壓縮至本機磁碟（建議放置於純英文或簡單路徑，如 `D:\Tools\bpm-toolbox\`，避免路徑過長或權限受限目錄）。

### 3. 一鍵啟動
進入解壓縮後的目錄，直接對著 **`run.bat`** 按兩下即可啟動！
* 腳本內建智慧搜尋引擎，會自動探測系統的 `JAVA_HOME` 或 `PATH` 中的 Java 執行環境。
* 腳本具備自體覆蓋更新銜接功能，支援軟體無痛升級。

## 三、核心功能操作教學

### 1. 修正佈署（BPM Deployer）

修正佈署專門用於解決人工拷貝 Hotfix / Patch 容易遺漏、路徑貼錯、或未注意成對 EAR/WAR 容器的痛點。採 **4 步驟引導式精靈（Wizard）**：

```
[步驟 1: 選擇來源] ➔ [步驟 2: 解析計畫] ➔ [步驟 3: 確認清單] ➔ [步驟 4: 執行佈署]
```

#### 操作步驟：
1. **步驟 1：選擇來源**
   * **BPM 根目錄**：選擇目前主機上的 BPM 安裝目錄（例如：`D:\NaNa\BPM`），系統會自動偵測版本號（如 `5.8.10.4`）。
   * **更新來源（ZIP 壓縮包 / 已解壓資料夾）**：支援拖曳或瀏覽標準 ZIP 壓縮包，**亦可直接拖入或選取已解壓之補丁實體資料夾**（相容 `.7z` / `.rar` 解壓目錄），零額外軟體依賴。
   * 點擊右下角「下一步：解析更新包」。

2. **步驟 2：解析計畫（自動語意分類）**
   * 系統會自動分析來源內部所有檔案，並進行智慧歸類：
     * **應用程式檔案（.class、JSP、XML 等）**：自動比對 Master Index，找出該檔案所屬的實體 JAR/WAR/EAR 容器路徑（含 `$*.class` 內部類別自動關聯）。
     * **資料庫升級腳本（.sql）**：自動標記為資料庫腳本，支援**點擊預覽**內容並一鍵複製，由 DBA 或人員於資料庫執行。
     * **說明與原始碼（.txt、.java 等）**：自動標註為參考檔案並略過佈署，不會產生誤報紅字。
   * **歧異項（AMBIGUOUS）智慧處理**：若某個 class 同時存在於多個容器中，系統會彈出對話框將成對的 EAR/WAR 合併為單一選項，勾選確認後自動雙向配置。
   * **內部類別遺漏防呆**：若更新包包含主類別但缺少同組的匿名內部類別（如缺少 `$1.class`），系統會以黃色警示提示，防止執行期引發 `NoSuchMethodError`。

3. **步驟 3：確認清單（自主勾選）**
   * 提供 **「表格檢視（Table）」** 與 **「階層樹狀檢視（Tree）」** 兩種模式：
     * 表格檢視：適合檢查每筆檔案的來源、目標容器、大小與狀態。
     * 樹狀檢視：以「容器 > 模組 JAR > 檔案」展開，可整批勾選模組。
   * 只有**已勾選且狀態為可佈署**的項目才會被寫入，提供最高操作自主權。

4. **步驟 4：執行佈署與安全防禦**
   * **伺服器運行中保護**：執行前系統會自動探測 WildFly / JBoss 是否處於開機運行中或檔案是否被鎖定。若伺服器未停機，系統會主動阻擋部署，避免檔案鎖死（Access Denied）或記憶體 Class 快取不同步。
   * **自動去重備份**：正式替換前，系統會將所有涉及修改的實體 EAR/JAR/檔案自動備份至 `.bpm-backups/` 目錄中，並建立快照。
   * **檔案時間戳保留**：注入/替換進去之檔案完全保留 ZIP 內的原始修改時間，方便日後稽核比對。
   * **部署完成工作流**：完成後提供一鍵「開啟部署目錄」、「檢視本次備份」與「部署新更新包」捷徑。

5. **備份與一鍵安全還原（Snapshot Inspector）**
   * 點擊介面上的「歷史備份」按鈕，可查看所有部署歷史紀錄。
   * 點選任一快照，即可查看該次部署修改了哪些檔案、新增了哪些檔案。
   * 若上線測試有問題，點擊**「還原此快照」**，系統將自動恢復原始檔案，並清除部署時新增的全新檔案，回到部署前狀態。

### 2. 路徑查詢（Path Query）

內部維運與開發排查必備工具，讓您不再需要大海撈針找 class 到底藏在哪個 JAR/WAR 裡面。

* **關鍵字即時搜尋**：輸入 Class 名稱（例如 `ProcessAccessor`）、JSP 檔名或路徑片段，立即列出所有收錄的容器內部路徑。
* **批次檔案/資料夾拖曳比對**：頂部橫幅（DropZone）支援直接拖曳整個 Hotfix ZIP 壓縮包或已解壓資料夾，一鍵自動完成內部數十筆檔案的容器路徑匹配，並自動略過 SQL 與參考文件。
* **跨版本比對**：支援切換不同 BPM 版本（如 5.8.9.4 vs 8.1.2.1），即時觀察該類別在不同版本中的模組變更或遷移位置。

---

### 3. 異動記錄（Release Diff）

專為顧問與客服團隊設計的版本履歷查詢中心：

* **分支與 Hotfix 差異比對**：選擇專案後，可清楚檢視兩個版本間（如 `5.8.10.3` 到 `5.8.10.4`）修改了哪些檔案、新增了哪些功能模組。
* **未發版追蹤**：開發管理者模式下可即時比對當前工作目錄與官方最新 Release 之間的未發版 Commit 清單。

---

### 4. 路徑掃描（Path Scanner）

僅在「開發管理版」中提供，用於建立全域版本字典索引：

1. 點擊「選擇目錄」選取實體安裝的 BPM 伺服器路徑。
2. 系統會自動解析 `server/default/deploy/` 下的所有 EAR/WAR/JAR。
3. 點擊「開始掃描」，系統深入解析容器內部數萬筆 class 路徑，並產出精簡的索引 JSON 檔，可供直接整合成 Master Index 字典檔。

## 四、軟體升級與自動更新

本工具具備無痛自動更新能力：

1. **開機背景檢測**：每次啟動工具時，會在背景自動向更新伺服器比對是否有更高版本。
2. **手動檢查更新**：隨時可點擊視窗邊角的「檢查更新」按鈕。
3. **一鍵升級流程**：
   * 當發現新版本時，視窗會跳出更新通知提示：「發現新版本 vX.Y.Z，是否立即更新並重新啟動？」。
   * 點擊「是」，系統將在背景下載對應當前模式的更新封裝，自動暫存並呼叫 `run.bat` 進行檔案覆蓋替換。
   * 軟體自動重新啟動，立即享受最新功能！

## 五、常見問題與排除 (FAQ)

### Q1：點擊 `run.bat` 後視窗一閃即逝（閃退），沒有開啟介面？
* **原因**：主機未安裝 Java，或 Java 環境變數未設定。
* **排除方式**：
  1. 打開命令提示字元（cmd），輸入 `java -version`。
  2. 若提示不是內部或外部命令，請安裝 Java 8（JRE 1.8）以上版本，並於系統環境變數設定 `JAVA_HOME`。

---

### Q2：執行部署時跳出「伺服器運行中被阻擋」或「檔案被鎖定 (Access is denied)」？
* **原因**：BPM 伺服器（WildFly / JBoss）正在運行中，Java 程序鎖定了 `NaNaWeb.war` 或 `nana-app.ear`，強行寫入會導致伺服器崩潰或檔案損壞。
* **排除方式**：
  1. 請先至 Windows 服務或主控台**停止 BPM 伺服器**。
  2. 確認伺服器 Java 程序完全結束後，回到工具點擊「重新整理」，再次執行佈署即可。

---

### Q3：更新包內有 `.sql` 檔案，工具會自動幫我執行到資料庫嗎？
* **回答**：**不會**。
* **原因**：為確保生產環境資料庫安全與交易隔離，工具不會自動對資料庫執行腳本。
* **建議做法**：工具會在解析清單中將 `.sql` 檔案標示出來，雙擊該項目即可在彈出視窗中檢視完整的 SQL 內容，並可一鍵複製給 DBA 或使用資料庫管理工具（如 DBeaver、SSMS）執行。

---

### Q4：部署後發現系統功能異常，如何快速恢復？
* **排除方式**：
  1. 在工具首頁或上方點擊**「歷史備份」**按鈕。
  2. 在左側快照清單中選取剛才執行的那一筆備份紀錄。
  3. 點擊右上角紅色的**「還原此快照」**。
  4. 系統將會以原始備份完整覆蓋還原，並自動刪除該次新增的檔案，讓伺服器百分之百復原至部署前的狀態。

---

### Q5：介面在某些 Windows 伺服器上會出現亂碼或方塊字（豆腐塊）嗎？
* **回答**：**不會**。
* 工具內建字型自動降級機制（微軟正黑體 / Segoe UI 動態配對）與全編碼相容防禦，完全杜絕 Windows 舊版環境缺字、豆腐塊或 CP950/MS950 Big5 檔名亂碼問題。
